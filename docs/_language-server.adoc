= Language server

`affogato lsp` speaks the Language Server Protocol over stdin and stdout. An
editor runs it as any server, as Neovim does with:

[source,lua]
----
vim.lsp.config('affogato', { cmd = { 'affogato', 'lsp' }, filetypes = { 'nix' } })
vim.lsp.enable('affogato')
----

[[example-editors]]
== Example editors

To try the server without configuring an editor, the flake provides VSCodium
and Zed already set up for it. From a checkout, run either of:

[source,shell]
----
nix develop .#vscodium -c codium-affogato path/to/folder
nix develop .#zed -c zed-affogato path/to/folder
----

Or enter the shell first, then run `codium-affogato` or `zed-affogato` with
the paths to open, as the editor's own command takes them. The shell also puts
`affogato` on the `PATH`.

== Any Nix file

* the linter's findings as diagnostics, with code actions for its fixes,
  `source.fixAll` and suppression comments;
* formatting of the file or of a range;
* go to definition, find references, document highlight and rename, also across
  the workspace for attributes reached through `import`;
* completion of the names in scope, builtins, keywords and the attributes of set
  literals, and a hover with Nix's documentation of each builtin;
* document symbols, folding and selection ranges, semantic tokens, and links on
  paths and URLs;
* rewrites of `a.b = x;` into `a = { b = x; };` and back, and of a string or an
  attribute name into the other quoting.

== nixpkgs

The server evaluates nixpkgs in the background as it starts and after a save.
For `pkgs.hello`, `lib.strings.concatStrings` or a name a `with pkgs;` brings
into scope, it gives completion, a hover with a package's version and
description or a function's doc comment, go to definition, and inlay hints with
package versions. Long evaluations report their progress.

== Packages

In a package fetched from a forge, a registry or a URL with its version, as
`affogato update` finds them, the code action *Update hello* runs what
`affogato update` does for that package, in the background with its progress
shown: it finds the latest version, prefetches the source and builds the
dependencies, such as `cargoDeps`, with a fake hash to learn theirs. The edits,
with those of its lock files, then reach the editor as a `workspace/applyEdit`
request, unless the document changed meanwhile; the file on disk is left to the
editor to save. Cancelling the progress stops the fetch or build under way. The
action's command, `affogato.updatePackage`, takes the document's URI and the
index of the package in it.

*Refresh the hashes of hello*, `affogato.refreshHashes`, does the same at the
version the package has, or at the commit it is pinned to, as
`affogato update --refresh` does: after a version changed by hand, say.

When a document opens or is saved, the server asks in the background for the
latest version of each of its packages, and shows those that have a newer one
as an information diagnostic, `outdated`, on their version, whose quick fix is
the update. What it learns is kept an hour, to stay under GitHub's rate limit.

The command `affogato.updateWorkspace` updates every package below the
workspace folders, or below the `file:` URIs it is given, as
`affogato update .` does, and sends the edits of every file it changed; a file
open in the editor with unsaved changes is left alone.

== Modules, flakes and devenv

* in a NixOS or home-manager module: completion of option names, a hover with
  an option's type, description and default, and go to its declaration;
* in a `flake.nix`: completion of inputs, outputs and their systems;
* in a `devenv.nix`: completion, hover and go to declaration of devenv's
  options, such as `languages.rust.enable`, read from the `devenv` command,
  which must be on the `PATH`.

[[language-server-settings]]
== Settings

The `affogato` section of the client's settings, or the
`initializationOptions`, may set:

[cols="1,3"]
|===
| `width`, `strict` | as the `affogato format` options
| `rules` | the ids of the <<lint-rules,lint rules>> to report, all when empty
| `nixpkgs.expr` | the expression nixpkgs is evaluated from, `import <nixpkgs> { }` unless `--nixpkgs` says otherwise
| `options.<name>.expr` | a set of options, NixOS's unless `--nixos-options` says otherwise; as in nixd, home-manager is one more name
| `checkUpdates` | whether to look for the latest version of the packages of the documents opened, `true` by default
|===

== Embedded languages

Strings often hold code in another language. The custom `affogato/injections`
request returns, for a document, the range and the language of each such
string, so that an editor can highlight it as that language. The language comes
from where the string stands:

[cols="3,1"]
|===
| String | Language

| `buildPhase = ''...''`, `postInstall`, `shellHook`, `script`, `enterShell`
| Bash
| `runCommand "name" { } ''...''`, `writeShellScript`, `writeShellApplication { text = ''...''; }`
| Bash
| `writers.writePython3 "name" { } ''...''`, `writeLua`, `writeRust`, …
| Python, Lua, Rust, …
| `writeText "config.json" ''...''`, `environment.etc."app/config.toml".text`
| that of the file name: JSON, TOML…
| `/* lua */ ''...''`, or `# language=sql` above the binding
| the one the comment names
|===
