== Suppressing a rule

A comment switches rules off, for `check` and `fix` alike: `ignore` for its
own line and the next one, `ignore-file` for the whole file. The rules are
separated by commas; `syntax-error` cannot be switched off.

[source,nix]
----
# affogato: ignore-file unused-let-binding, empty-let-in
[
  # affogato: ignore bool-comparison
  (x == true)
  (y == true) # affogato: ignore bool-comparison
]
----

== Language server

`affogato lsp` speaks the Language Server Protocol over stdin and stdout, from
the same parser as the other commands. It answers with:

* the linter's findings, as diagnostics, for the last of the changes of a
  document that wait to be read, and none for those before;
* formatting, indented by the request's `tabSize`, of the file or of the
  bindings a range touches, the whole file when it touches none;
* go to definition, find references, document highlight, and rename, which
  refuses up front a name that is not defined in the file, such as a builtin;
  go to definition also from a selection, as `a` in `x.a` or `x ? a`, to where
  the set literal bound to `x` in the file binds it;
* completion of the names in scope, the builtins, with `builtin` as their
  detail, and the keywords, with snippets such as `let … in` for an editor that
  takes them, of the attributes of `builtins` after `builtins.`, of those of
  nixpkgs after `pkgs.` and `lib.`, unless the file binds them otherwise than as
  a parameter, and of a set literal a `let` or `rec` set binds after its name
  and a dot, as `x.a.`, through the names bound to it and its `inherit`s;
* completion of the names in scope, the builtins and the keywords, of the
  attributes of `builtins` after `builtins.`, and of those of nixpkgs after
  `pkgs.` and `lib.`, unless the file binds them otherwise than as a parameter;
* in a `flake.nix`, completion of the attributes of a flake, of an input
  (`url`, `follows`, …) and of the outputs, with the systems under those that
  have one, as `packages.x86_64-linux`, and of the inputs it declares as the
  formals of `outputs` and after the name it binds them to, as `inputs.`;
* on such an attribute, as `pkgs.hello` or `lib.strings.concatStrings`: a hover
  with the version, description and homepage of a package, the doc comment of
  a function, the value of a number, string or Boolean, or the error an alias
  throws; go to definition, at the package's `meta.position` or where the
  attribute or function is defined; and the version or type, and the
  description or doc comment, of a completion item as the editor resolves it;
* inlay hints with the version of each package selected from nixpkgs, those
  evaluated within 200 ms of the request, and the others once evaluated, as the
  server then sends `workspace/inlayHint/refresh` to an editor that supports it;
* in a module, the same for a selection from one of its arguments other than
  `pkgs`, `lib`, `config` and `options`, as `inputs.agenix.packages`, looked up
  among the arguments the option sets give their modules, the special ones
  first; a `${...}` name that is itself a selection from nixpkgs giving a plain
  string, as `${pkgs.stdenv.hostPlatform.system}`, counts as that name;
* in a module, a function of `config`, `lib`, `pkgs` or `modulesPath`: the
  completion of option names as a binding's name is typed, and on such a name a
  hover with the option's type, description, default and example, and go to its
  declaration; a hover on a group of options, as `services.nginx`, lists the
  names under it; a set bound to an option path, also through `mkIf`, `mkMerge`
  and the like, continues that path, `config.` is skipped, and each attribute
  of an `attrsOf` submodule takes a name of its own, as in
  `virtualHosts."example.org".root`;
* the same completion, hover, definition and hints for the names a `with` of
  nixpkgs brings into scope, as `hello` in `with pkgs; [ hello ]`: a name bound
  in the file or a builtin is not one, and the innermost `with` that has the
  name gives it, up to a `with` of something other than nixpkgs;
* completion and go to definition for the names a `with` of a set literal of
  the file brings into scope, written in place or reached through its names
  and selections, as `with s.a;`;
* document symbols, folding ranges, selection ranges and semantic tokens;
* links on the paths without interpolation, the URIs, and the strings that are
  an http or https URL, and go to definition on such a path, both to the
  `default.nix` of a directory, as `import` and `callPackage ./foo { }` read it;
* code actions for the linter's fixes and suppression comments,
  `source.fixAll` for all the fixes, and rewrites: of a binding, `a.b = x;` into
  `a = { b = x; };` and back, of a string, in the other quoting when that
  keeps its value, and of an attribute name, `a` into `"a"` and back when the
  name is an identifier and no keyword;
* `affogato/injections`, a request of its own, which takes a `textDocument` and
  lists the strings written in another language: the range between their
  quotes, and a `kind` of `shell`, `named` (the `value` a comment names, such as
  `lua`) or `file` (a file name whose type tells the language).

The `affogato` section of the `workspace/didChangeConfiguration` settings, or
of the client's configuration, which the server asks for with
`workspace/configuration` once initialized and when told it changed, or the
`initializationOptions`, may set the `width`, `strict`, and the `rules` to
lint with, a list of ids, all when empty, and `nixpkgs.expr`, the expression
nixpkgs is evaluated from, `import <nixpkgs> { }` unless `--nixpkgs` says
otherwise, and `options`, a name for each set of options with the `expr` it is
evaluated from, `{ nixos.expr = "(import <nixpkgs/nixos> { configuration = { };
}).options"; }` unless `--nixos-options` says otherwise; as in nixd, a
home-manager set is one more name. Options are evaluated when first asked for,
in the same context as nixpkgs, so that a flake both expressions read, as with
`builtins.getFlake`, is evaluated once. The server evaluates it on a thread of its own as it starts, keeps
the values, and evaluates it again after a file is saved; a completion that
waits for it more than 200 ms comes back marked incomplete, so that the editor
asks again.

An editor runs it as any server, as Neovim does with:

[source,lua]
----
vim.lsp.config('affogato', { cmd = { 'affogato', 'lsp' }, filetypes = { 'nix' } })
vim.lsp.enable('affogato')
----

== treefmt

`format` and `fix` follow the
https://treefmt.com/latest/reference/formatter-spec/[treefmt formatter spec]:

[source,toml]
----
[formatter.affogato]
command = "affogato"
options = ["fix"]
includes = ["*.nix"]
----
