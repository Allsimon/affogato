= Status

include::_lang-tests.adoc[]

Checked against Nix 2.35.6 and nixpkgs `d4f25a3e5620` on x86_64-linux.

Language tests::
affogato passes {lang-passed} of the {lang-tests} tests of NixOS/nix's
`tests/functional/lang` suite and {tvix-passed} of the {tvix-tests} of Tvix's
`eval/src/tests/tvix_tests`. The others are listed with reasons in
`language/src/test/java/lang-skip.txt`.

Top-level packages::
For every top-level nixpkgs attribute (`scripts/toplevel-drvpaths.nix`),
affogato and `nix-instantiate` produce 24,311 identical drvPaths. 717 attributes
fail in both, and none differ or fail in only one evaluator:
+
[cols="3,1,1",options="header"]
|===
|Evaluator |Time |Peak RSS
|`nix-instantiate` |1 min 54 s |9.3 GB
|affogato on the JVM, `-j 1` |1 min 1 s |8.0 GB
|affogato on the JVM, `-j 4` |21 s |9.1 GB
|===
+
With more than one worker, helper threads force ahead of demand the values
the output walks, as numtide/iets does; the output and errors are those of one
thread. The default is the number of processors, up to 4.

Heavier attributes::
`scripts/parity.sh` finds identical drvPaths for `firefox`, `chromium`,
`libreoffice`, `texliveFull`, `haskellPackages.pandoc`, `nixosTests.firefox`,
`pkgsCross.aarch64-multiplatform.hello` and `pkgsStatic.hello`.

Formatter::
`affogato format --check` finds nixpkgs' 45,377 files formatted, as
`nixfmt --check` 1.5.0 does. Both go through the files sequentially:
+
[cols="3,1,1",options="header"]
|===
|Formatter |Time |Peak RSS
|nixfmt |2 min 40 s |1.4 GB
|affogato on the JVM |21 s |1.7 GB
|affogato on the JVM, `-Xmx512m` |21 s |0.74 GB
|affogato as a native image |37 s |0.8 GB
|===

== Not supported

* Fetching: `fetchurl`, `fetchTarball` and `fetchGit` fail; `fetchTree` takes
  only a locked input with a `narHash`, already in the store; and `getFlake`
  only a local flake, `/dir`, `path:/dir` or `git+file:///dir`, whose locked
  inputs are in the store, as after building it or `nix flake archive`. The
  flake's own files are read in place, not from a copy in the store, so its
  `outPath` is the directory and the paths it gives derivations differ from
  Nix's.
  The language server has `nix flake prefetch` copy a locked input missing from
  the store out of Nix's own fetch cache, without the network, as Nix keeps the
  inputs it evaluates there rather than in the store.
* Import from derivation.
* Content-addressed and impure derivations.
* `--xml` output.
* The `--lint-*` flags.
* Rejection of NUL bytes in strings, and UTF-8 validation in `toJSON`.
